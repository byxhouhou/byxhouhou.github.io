2. UART

2.1 汽车电子中 UART 的使用场景

UART 是一种低成本的异步串行通信方式，常用于芯片、模组和调试设备之间的点对点通信。

常见业务场景：

  1. 低速控制命令
  2. 日志打印
  3. 状态信息交互

优势：

  1. 硬件简单，只需要 TX、RX，必要时加 GND
  2. 成本低，MCU 基本都自带 UART 外设
  3. 使用简单，调试方便
  4. 不需要时钟线，连接方式简单

缺点：

  1. 通信速率相对较低，吞吐能力有限
  2. 点对点通信为主，不适合复杂多节点通信
  3. 没有天然帧边界，需要上层协议自己分帧
  4. 没有标准 ACK / 重传机制，可靠性需要上层保证
  5. 对波特率匹配和时钟误差比较敏感
  6. 抗干扰能力不如 CAN、RS485 这类差分通信

2.2 UART 的核心机制

2.2.1 异步通信机制

UART 是一种异步串行通信方式。所谓异步，是指通信双方之间没有共享时钟线，通常只需要 TX、RX 和 GND 即可完成基本通信。

UART 通过 TX/RX 线上相对于 GND 的电平变化来表示 0 和 1，从而完成数据传输。

这个机制解决的是：没有共享时钟线也能通信的问题。
也就是说，UART 不依赖额外的时钟信号，而是通过提前约定通信参数，让发送方和接收方按照相同规则完成数据收发。

2.2.2 波特率机制

2.3 工程中如何配置 UART

2.3.1 配置使用的 IO

双向 UART 通信通常需要 TX、RX、GND。第一步应结合硬件原理图、芯片手册和 PinMux 表，确认所选 UART 实例及其可用引脚。

MCU 引脚通常支持多种复用功能，并不是任意 GPIO 都能映射到任意 UART。以 UART1 为例，需要将对应引脚配置为 UART1_TX 和 UART1_RX 的复用功能，同时确认：

  • TX 与 RX 是否交叉连接
  • 双方是否共地
  • IO 电平是否兼容
  • 是否需要电平转换芯片
  • PinMux、上下拉和驱动能力是否正确

2.3.2 配置 UART 外设时钟

UART 外设需要时钟源才能工作，因此需要先打开 UART 外设时钟。
UART 的波特率本质上是由外设时钟分频得到的，所以如果时钟源配置错误，即使代码里设置的是 115200，实际输出的波特率也可能不准确。
因此工程中需要确认：

  • UART 外设时钟是否打开
  • UART 时钟源是否正确
  • 时钟频率是否和波特率计算一致
  • 系统切换时钟或低功耗恢复后是否需要重新配置

如果串口出现乱码，除了检查波特率配置，也要检查系统时钟和 UART 外设时钟是否正确。

2.3.3 配置波特率和帧格式

UART 通信双方必须使用一致的通信参数。

常见参数包括：

  • 波特率：例如 9600、115200、921600
  • 数据位：通常为 8 bit
  • 校验位：无校验、奇校验、偶校验
  • 停止位：1 位或 2 位

常见配置 115200 8N1 的含义是：

  • 115200：波特率
  • 8：8 个数据位
  • N：无校验位
  • 1：1 个停止位

如果双方参数不一致，常见现象就是乱码、接收错误或者无法正常通信。

2.3.4 配置发送和接收方向

UART 可以只发送、只接收，也可以同时支持发送和接收。

工程中需要根据业务场景开启对应功能：

  • 只打印日志：通常只需要 TX
  • 只接收外部数据：需要 RX
  • 与模组双向通信：需要 TX + RX

例如 MCU 和 4G 模组通信时，一般需要同时开启 TX 和 RX，因为 MCU 既要发送 AT 命令，也要接收模组返回的数据。

2.3.6 配置中断、DMA 和 Buffer

如果使用中断接收，需要配置 UART RX 中断，并在 NVIC 中设置中断优先级。

如果使用 DMA 接收，需要额外配置：

  • DMA 通道与 UART RX Request
  • 源地址：UART 接收数据寄存器
  • 目标地址：接收 Buffer
  • 传输长度与循环模式
  • DMA 中断或回调

同时还需要设计软件接收缓冲区，例如：

  • 普通数组 Buffer
  • 环形缓冲区 RingBuffer
  • RTOS Queue
  • RTOS StreamBuffer

2.3.8 配置和处理错误状态

UART 工程中还需要关注错误状态，例如：

  • Parity Error：校验错误
  • Framing Error：帧错误
  • Overrun Error：溢出错误
  • Noise Error：噪声错误
  • Break Detect：总线长时间保持低电平

其中 Overrun 比较常见，表示 UART 已经收到新数据，但旧数据还没有被及时取走，导致数据被覆盖或丢失。

错误处理至少需要完成：

  1. 读取并记录错误状态
  2. 按芯片要求清除标志
  3. 丢弃不完整帧
  4. 必要时重启 RX、DMA 或整个 UART
  5. 统计连续错误并上报业务层

2.4 UART 常见问题与面试题

2.4.1 基础题

问题 1：UART 用于什么？

回答：UART 是一种异步串行通信方式，主要用于 MCU、传感器、PC、蓝牙、GPS 模块之间的数据交换，特点是硬件简单、成本低、不需要共享时钟线。

问题 2：为什么需要 Start Bit 和 Stop Bit？

回答：Start Bit 标记一个字符帧开始，并为接收方提供采样时间基准；Stop Bit 标记当前字符结束，并让总线恢复空闲高电平。接收方检测到 Start Bit 后，会根据波特率在后续数据位中心附近采样。

问题 3：115200 表示什么？

回答：表示波特率为 115200 baud。在常见二进制 UART 中，可以近似理解为每秒传输 115200 bit。

问题 5：为什么需要 GND？

回答：UART 是单端信号，TX 和 RX 的电平必须基于共同参考电位判断，因此通信双方通常需要共地。

问题 6：双向 UART 通信最少需要几根线？

回答：通常需要 TX、RX、GND 三根线。若只做单向发送，最少可以使用 TX 和 GND 两根线。

追问：为什么有时开发板只接 TX 和 RX 也能通信？

回答：两块设备可能已经通过 USB、电源或其他连接形成了共同地线，但这种连接依赖隐含条件，不应作为正式硬件设计。

2.4.2 进阶题

问题 1：什么是轮询接收？优缺点是什么？

回答：CPU 持续检查接收状态。优点是实现简单、调试方便；缺点是浪费 CPU 时间，且程序阻塞时可能无法及时处理其他任务。

问题 2：什么是中断接收？

回答：UART 收到数据或达到 FIFO 阈值后触发中断，CPU 进入 ISR 读取数据并通知后续处理。

问题 3：中断相比轮询有什么优势？

回答：减少无效查询，提高 CPU 利用率和系统响应能力。但数据量较大时，每字节中断仍可能带来较高开销。

问题 4：什么是 DMA？

回答：DMA 是硬件数据搬运机制。CPU 配置源地址、目标地址和传输长度后，DMA 可以独立完成数据搬运，无需 CPU 参与每一次复制。

问题 5：DMA 最大的价值是什么？

回答：降低 CPU 占用和中断频率。DMA 不会突破 UART 波特率决定的物理传输速度。

问题 6：为什么 UART 经常和 DMA 一起使用？

回答：UART 持续接收大量数据时，逐字节中断会增加 CPU 负担。DMA 可以批量搬运数据，并在半传输、传输完成或 UART IDLE 时通知 CPU。

问题 7：FIFO 是什么？

回答：FIFO 是先进先出硬件缓冲区，用于暂存收发数据。合理配置 FIFO 阈值可以降低中断频率，并为 CPU 或 DMA 留出处理时间。

问题 8：波特率不一致会发生什么？

回答：接收端的采样点会逐渐偏离数据位中心，造成数据错误、乱码或 Framing Error。

问题 9：UART 接收 GPS 数据时，是否应该在 UART_IRQHandler() 中直接解析？

回答：不建议。ISR 应尽量短，只完成读取寄存器、写入 RingBuffer 或通知任务等必要操作。GPS 协议解析属于业务逻辑，应放在任务上下文中处理。

问题 10：DMA 正在写 Buffer 时，CPU 同时读取是否有问题？

回答：可能读到正在更新的数据，产生半包或数据一致性问题。Half Complete / Complete 中断只能提供可处理区域的时间边界，工程中还需要双缓冲、环形缓冲区、所有权管理，以及在带 Cache 的 MCU 上正确维护 Cache 一致性。

问题 11：为什么 UART 通信距离不能太长？

回答：UART 通常使用单端电平，抗共模干扰能力较弱，且没有差分传输和总线终端机制。长距离场景通常应转换为 RS485、CAN 等物理层。

问题 12：UART 为什么不适合高速传输？

回答：UART 没有共享时钟，允许的时钟误差和采样裕量有限；同时每个字符还包含 Start/Stop 等额外开销。高速、大吞吐场景通常更适合 SPI、USB 或 Ethernet。

3. SPI

3.1 SPI 的使用场景

SPI 主要用于 MCU 与板级外设之间的高速同步通信，典型特点是距离短、速度高、由主机控制通信时序。

汽车电子中的常见场景：

  1. 外部 Flash、EEPROM 等存储器
  2. PMIC、SBC 等电源管理芯片
  3. 高速传感器、ADC、DAC
  4. 显示屏、触摸芯片和 HMI 外设
  5. SoC 与 MCU 之间的板级数据通道

优点：

  1. 传输速度快
  2. 协议简单，软件开销低
  3. 主机控制时钟，时序确定性较好
  4. 全双工通信
  5. 适合与 DMA 配合
  6. 支持一主多从

缺点：

  1. 占用 IO 较多
  2. 不适合长距离通信
  3. 没有标准 ACK、CRC 和重传机制
  4. 没有设备地址机制
  5. 主从关系明显，从机通常不能主动发送
  6. 高速下容易遇到信号完整性问题

3.2 SPI 的核心机制

3.2.1 同步通信机制

SPI 是同步通信。主机输出 SCLK，从机根据时钟边沿移位和采样，因此双方不需要依靠各自时钟推算每个 bit 的采样时刻。

3.2.2 主从控制机制

SPI 采用主从控制机制，通信需要由主机主动发起，从机被动响应。

从机若需要主动通知主机，通常还要增加 DATA_READY 或中断 GPIO，由主机收到通知后发起 SPI 事务。

3.2.3 片选机制

SPI 没有 IIC 的设备地址机制，通常通过独立 CS 线选择从设备：

部分器件要求一条完整命令期间 CS 必须保持有效，不能在命令、地址和数据之间提前拉高。

3.2.4 全双工移位机制

SPI 是全双工通信。每产生一个 SCLK，主机和从机都会同时移出 1 bit，也同时采样 1 bit。

因此：

  • 主机发送命令时，也会同步收到数据
  • 主机读取数据时，仍需要发送 Dummy Byte 产生时钟
  • 发送长度和接收长度在硬件层通常是对应的

3.2.5 时钟模式：CPOL / CPHA

CPOL 表示 SCLK 空闲电平：

  • CPOL = 0：空闲时为低电平
  • CPOL = 1：空闲时为高电平

CPHA 表示在哪个有效边沿采样：

  • CPHA = 0：第一个有效边沿采样
  • CPHA = 1：第二个有效边沿采样

CPOL 和 CPHA 组合形成 Mode 0~3。主从配置不一致时，常见现象是数据整体移位、最高位或最低位错误、偶发读错。

3.2.6 数据帧与位序机制

SPI 通常以固定数据宽度收发，例如 8 bit、16 bit 或 32 bit。还需要确认位序：

  • MSB First：高位先发
  • LSB First：低位先发

如果协议字段长度大于一个传输单元，还需要显式约定多字节数据的字节序。

3.2.7 SPI 事务机制

SPI 通信通常围绕一次完整事务进行：

  1. CS 拉低
  2. 发送命令
  3. 发送地址或者参数
  4. 发送/接收数据
  5. CS 拉高

器件手册通常还会规定：

  • CS 建立时间和保持时间
  • 命令与数据之间是否需要等待
  • 最大 SCLK 频率
  • 连续读写是否支持地址自增

3.3 工程中如何配置 SPI

3.3.1 确认硬件资源

需要结合原理图和芯片手册确认：

  • SPI Controller 实例
  • SCLK、MOSI、MISO、CS PinMux
  • 主从设备的 IO 电平
  • CS 是否由硬件或 GPIO 控制
  • 是否存在 READY、BUSY、DATA_READY 等辅助引脚
  • 板级走线是否满足目标频率

3.4.1 基础题

问题 1：SPI 为什么通常比 UART 快？

回答：SPI 由主机提供同步时钟，不需要 Start/Stop Bit，并且通常可使用推挽输出和更高时钟频率。但最终速度仍受 MCU、从设备和信号完整性限制。

问题 2：SPI 为什么需要 SCLK？

回答：SCLK 为主从双方提供统一的移位和采样节奏，决定每个 bit 在什么时间更新和读取。

问题 3：SPI 常见的四根线分别是什么？

回答：SCLK、MOSI、MISO、CS。部分单向或三线 SPI 会省略或复用其中的信号。

问题 4：SPI 和 UART 有什么区别？

回答：SPI 是同步、主从式、通常全双工的板级通信；UART 是异步、点对点、通过波特率约定采样节奏的串行通信。SPI 通常更快但占用更多 IO。

问题 5：SPI 和 IIC 有什么区别？

回答：SPI 通过独立 CS 选择设备，通常速度更高且支持全双工；IIC 通过地址选择设备，只使用 SDA/SCL 两根信号线，但属于半双工且速率通常更低。

问题 6：什么是主机和从机？

回答：主机负责选择从机并产生时钟；从机只能在被选中且收到时钟后参与传输。

3.4.2 进阶题

问题 1：多个 SPI 从设备挂在同一总线上要注意什么？

回答：

  • 每个从设备使用独立 CS
  • 同一时刻只能有一个 CS 有效
  • 不同设备可能使用不同 SPI Mode 和最大频率
  • 未选中的从设备必须释放 MISO
  • 整个事务需要互斥保护，不能在中途切换设备

问题 2：SoC 与 MCU 使用 SPI 通信时，通常如何设计协议？

通常不会裸传数据，而是设计上层协议：

常见机制包括：

  • 启动握手与版本检查
  • READY / DATA_READY GPIO
  • 序列号、超时与失败重试
  • CRC 校验
  • 流量控制
  • 复位和休眠唤醒后的重新同步

这样可以处理启动时序、复位、休眠唤醒、通信错误等问题。

问题 3：SPI 读取数据时，第一个字节为什么经常无效？

主机发送命令的同时，也会从 MISO 收到一个字节。但此时从设备可能还没有处理完命令，也还没有准备好返回有效数据，所以这个同步收到的字节通常是无效的。

问题 4：SPI 通信中直接发送结构体有什么风险？

回答：结构体可能包含编译器填充字节，并且不同处理器可能存在字节序、对齐方式、类型宽度和 ABI 差异。跨芯片通信时应该显式定义协议字段，并逐字段序列化，而不是直接发送结构体内存。

问题 5：为什么 SPI 只读数据时仍要发送 Dummy Byte？

回答：SPI 的收发由同一时钟驱动。主机只有发送数据并产生 SCLK，从机才能移出返回数据。Dummy Byte 的具体值通常是 0x00 或 0xFF，需要根据器件协议选择。

问题 6：SPI DMA 完成是否代表事务已经结束？

回答：不一定。DMA 完成只表示数据已在 SPI 数据寄存器与内存之间搬运完毕，还需要确认 SPI Busy 状态清除、最后一个 bit 已经发送完成，然后才能安全拉高 CS。

4. IIC（I2C）

4.1 IIC 的使用场景

IIC 是一种双线、同步、支持多设备寻址的板级通信总线，常用于速率要求不高、外设数量较多的场景。

汽车电子中常见应用包括：

  1. PMIC、SBC 和电源监控芯片
  2. EEPROM、温度传感器和低速 ADC
  3. 触摸芯片、RTC 和板级配置器件
  4. 摄像头、显示屏等设备的控制通道

优点：

  1. 只需要 SDA、SCL 两根信号线
  2. 通过设备地址支持一主多从
  3. 协议和硬件资源占用较少
  4. 适合低速配置和状态读取

缺点：

  1. 依赖上拉电阻，总线负载会限制速率
  2. 半双工，吞吐量低于 SPI
  3. 容易出现 NACK、Clock Stretch 和总线锁死
  4. 不适合长距离和强干扰环境

4.2 IIC 的核心机制

4.2.1 开漏输出与上拉机制

SDA 和 SCL 通常采用开漏输出。设备只能主动拉低总线，释放后由上拉电阻将电平拉高。

这个设计允许多个设备共享总线，并避免两个设备分别输出高、低电平时产生硬件短路。

4.2.2 Start、Repeated Start 与 Stop

在 SCL 为高电平时：

  • SDA 从高变低表示 Start
  • SDA 从低变高表示 Stop

4.2.3 地址与读写方向

常见 IIC 使用 7 位设备地址，在线路上传输时还会附加 1 位读写方向位。

工程中需要确认 SDK 接口要求传入的是：

  • 原始 7 位地址
  • 还是已经左移并包含读写位的 8 位地址

地址格式理解错误是设备持续 NACK 的常见原因。

4.2.4 ACK / NACK 机制

每传输 8 bit 数据后，接收方会在第 9 个时钟周期返回 ACK 或 NACK。

  • ACK：当前字节已接收，可以继续传输
  • NACK：拒绝当前传输，或表示读取结束

4.2.5 仲裁与 Clock Stretch

多主机场景下，主机通过监控 SDA 实际电平进行仲裁。若发送高电平时读到低电平，说明仲裁失败。

从机也可以通过持续拉低 SCL 延迟通信，这称为 Clock Stretch。驱动必须设置合理超时，避免任务永久阻塞。

4.2.7 总线速率与上升时间

IIC 高电平依赖上拉电阻与总线电容共同充电，因此信号上升时间不是瞬时的。

上拉电阻过大时：

  • 上升沿变慢
  • 高速模式下可能无法达到有效高电平
  • 逻辑分析仪可能看到波形边沿圆钝

上拉电阻过小时：

  • 设备拉低总线时电流增大
  • 可能超过器件灌电流能力
  • 功耗增加

因此上拉阻值需要结合供电电压、总线电容、目标速率和器件手册选择，不能简单固定为某一个经验值。

  3. 设备未上电或仍处于复位状态
  4. Repeated Start 时序不正确
  5. EEPROM 写入后未等待内部写周期
  6. Clock Stretch 超时
  7. SDA 被从设备持续拉低，导致总线 Busy
  8. 多任务同时访问同一总线

4.4.2 总线恢复

若从设备在传输中途复位，可能持续拉低 SDA。常见恢复方法：

  1. 暂时关闭 IIC 控制器
  2. 将 SCL 配置为 GPIO
  3. 输出最多 9 个恢复时钟
  4. 生成 Stop 条件
  5. 重新初始化 IIC

该方法依赖从设备能够通过额外时钟退出未完成传输，并不保证适用于所有器件。恢复失败时还可能需要复位或重新上电从设备。

4.4.3 调试顺序

建议使用逻辑分析仪直接查看地址、读写方向、ACK 和字节内容。只查看软件返回值通常无法区分地址错误、时序错误和设备未上电。

4.4.4 基础题

问题 1：为什么 IIC 需要上拉电阻？

回答：IIC 使用开漏输出，设备只能主动拉低总线，不能主动输出高电平。上拉电阻负责在所有设备释放总线时恢复高电平，同时支持多设备线与和仲裁。

问题 2：ACK 和 NACK 分别表示什么？

回答：每传输 8 bit 后，接收方在第 9 个时钟返回应答。ACK 表示接受当前字节；NACK 可能表示地址无人响应、从机暂时无法接收，也可能是主机读取最后一个字节时主动结束传输。

问题 3：Repeated Start 有什么作用？

回答：在不释放总线的情况下重新发起 Start，常用于先写寄存器地址、再切换到读方向。它能保证整个读寄存器过程是一个连续事务。

问题 4：为什么 IIC 通常比 SPI 慢？

回答：IIC 使用开漏和电阻上拉，上升速度受总线电容限制；每个字节还需要 ACK，并包含地址和 Start/Stop 等协议开销。SPI 使用主机时钟和推挽信号，通常可运行在更高频率。

问题 5：7 位地址和 8 位地址有什么区别？

回答：7 位地址是设备地址本体。在线路上传输时，它会左移一位并在最低位附加 R/W。SDK 有的要求传入 7 位地址，有的要求传入已移位值，必须查看接口定义。

4.4.5 进阶题

问题 1：如何定位设备一直 NACK？

回答：依次检查设备供电和复位、SDA/SCL 上拉、设备地址格式、总线频率、器件启动等待时间，以及设备是否处于 EEPROM 写周期或其他 Busy 状态。

问题 2：为什么 SDA 被拉低后总线无法再次通信？

回答：从设备可能认为当前字节尚未传完，仍等待后续 SCL。控制器复位并不会自动改变从设备状态，因此需要额外时钟、Stop、从设备复位或重新上电。

问题 3：为什么不能只在每次发送一个字节时加锁？

回答：一次寄存器访问可能包含 Start、地址、寄存器地址、Repeated Start、数据和 Stop。锁必须覆盖完整事务，否则其他任务可能插入操作并破坏状态机。

问题 4：IIC DMA 完成后为什么仍不能立即释放总线？

回答：DMA 完成只代表内存与数据寄存器之间的搬运结束，控制器可能仍在发送最后一个字节或生成 Stop。需要继续检查 IIC Busy、Transfer Complete 等状态。

问题 5：Clock Stretch 和总线锁死有什么区别？

回答：Clock Stretch 是从机按协议暂时拉低 SCL，等待处理完成；总线锁死通常是异常状态，SDA 或 SCL 长时间无法释放。两者都必须设置超时，但恢复策略不同。

5. CAN

5.1 CAN 的使用场景

CAN 是面向多节点、具有仲裁与错误处理能力的差分总线，是汽车电子中最常用的通信方式之一。

典型场景：

  1. ECU 之间的周期信号通信
  2. UDS 诊断和 Bootloader 刷写
  3. 车身、动力、底盘域控制
  4. 网络管理与节点唤醒

优点：

  1. 差分传输，抗干扰能力强
  2. 支持多主机与无损仲裁
  3. 自带 CRC、ACK 和错误检测
  4. 节点错误会被限制，避免持续破坏总线

缺点：

  1. Classic CAN 单帧载荷只有 8 字节
  2. 总线长度与波特率相互制约
  3. 需要收发器和正确的终端电阻
  4. 过滤器、Message Buffer 和错误状态管理较复杂

5.2 CAN 的核心机制

5.2.1 差分传输

CAN Controller 负责协议控制，CAN Transceiver 负责将逻辑电平转换为 CANH/CANL 差分信号。

总线存在两种逻辑状态：

  • Dominant：显性位，通常表示逻辑 0
  • Recessive：隐性位，通常表示逻辑 1

以常见高速 CAN 为例，隐性状态下 CANH 和 CANL 都接近 2.5V；显性状态下 CANH 升高、CANL 降低，接收器通过两者差分电压判断逻辑状态。

CAN Controller 和 CAN Transceiver 是两个不同层次：

  • Controller：负责帧格式、仲裁、CRC、过滤器、错误计数
  • Transceiver：负责逻辑电平与 CANH/CANL 物理信号转换

5.2.2 多主机与无损仲裁

所有节点都可以主动发送。多个节点同时发送时，报文 ID 更小、优先级更高的节点赢得仲裁。

仲裁失败的节点不会破坏当前报文，而是在总线空闲后重新发送，因此称为无损仲裁。

更准确地说，节点会边发送边监控总线。当自身发送 Recessive，却检测到 Dominant 时，说明存在更高优先级报文，当前节点立即停止发送并转为接收。

5.2.3 帧结构

需要区分：

  • 标准帧：11 位 ID
  • 扩展帧：29 位 ID
  • Classic CAN：最大 8 字节数据
  • CAN FD：最大 64 字节数据，并可切换数据段速率

Classic CAN 数据帧主要包含：

ACK 槽由正确接收到报文的其他节点写入显性位。发送节点通常不会给自己的报文 ACK，因此总线上只有一个正常模式节点时，可能持续出现 ACK Error。

5.2.4 错误检测与状态机

CAN 可检测 Bit、Stuff、CRC、Form、ACK 等错误，并通过 TEC、REC 错误计数器管理节点状态：

错误类型：

  • Bit Error：发送值与总线实际值不一致，仲裁和 ACK 阶段除外
  • Stuff Error：连续相同比特数量违反位填充规则
  • CRC Error：接收端计算的 CRC 不一致
  • Form Error：固定格式区域出现非法电平
  • ACK Error：发送端没有检测到接收节点 ACK

5.2.5 位填充与同步

CAN 使用 NRZ 编码。为保证总线上持续出现可用于同步的边沿，经典帧的相关区域中连续出现 5 个相同比特后，会自动插入一个相反比特。

接收节点依据总线边沿进行重同步。SJW 限制单次重同步允许调整的最大时间，用于补偿节点间时钟误差和传播延迟。

5.2.6 CAN FD 的关键变化

CAN FD 相比 Classic CAN 增加：

  • 最大 64 字节 Payload
  • 更长 DLC 编码
  • BRS：数据段切换到更高波特率
  • ESI：发送节点错误状态指示
  • 更强的 CRC 设计

CAN FD 仲裁段仍以 Nominal Bit Rate 工作，只有启用 BRS 时数据段才切换到 Data Bit Rate。

5.4.2 Bus Off 恢复

工程中需要明确：

  • 使用硬件自动恢复还是软件恢复
  • 恢复前等待多久
  • 是否重新初始化控制器
  • 是否通知网络管理和业务层
  • 连续 Bus Off 是否进入降级状态

按照 CAN 规范，Bus Off 节点需要观察到规定数量的连续隐性位序列后才满足重新加入总线的基础条件。实际项目通常还会增加软件等待、错误计数、重新初始化和故障上报。

  1. 总线上是否存在另一个正常模式节点

  3. 收发器是否处于 Normal Mode
  4. CANH/CANL 是否接反或断路
  5. 终端电阻是否正确
  6. 对端是否实际接收到合法帧

5.4.4 基础题

问题 1：CAN 为什么抗干扰能力强？

回答：CAN 使用差分信号，接收器关注 CANH 与 CANL 的电压差，对两根线同时受到的共模干扰不敏感。同时协议还具有 CRC、位监控、帧格式检查和自动重发。

问题 2：CAN 如何进行仲裁？

回答：多个节点同时发送时会边发送边读取总线。Dominant 会覆盖 Recessive。发送 Recessive 却读到 Dominant 的节点失去仲裁，并立即停止发送。

问题 3：为什么通常说 ID 越小优先级越高？

回答：ID 从高位开始参与仲裁，逻辑 0 为 Dominant。数值更小的 ID 通常更早发送 Dominant，因此赢得仲裁。严格来说，仲裁还会受到帧格式相关控制位影响。

问题 4：标准帧与扩展帧有什么区别？

回答：标准帧使用 11 位 ID，扩展帧使用 29 位 ID。扩展帧可提供更多标识符，但仲裁字段更长、协议开销更大。

问题 5：CAN 为什么需要终端电阻？

回答：终端电阻用于匹配总线特征阻抗并抑制信号反射。高速 CAN 通常在总线两端各放置 120 欧姆电阻，断电测量 CANH 与 CANL 之间常见约 60 欧姆。

问题 6：只有一个 CAN 节点时能正常发送吗？

回答：正常模式下通常不能持续成功，因为没有其他节点在 ACK 槽返回显性位。可以使用内部或外部 Loopback 模式进行单节点测试。

5.4.5 进阶题

问题 1：Error Active、Error Passive 和 Bus Off 如何迁移？

回答：控制器依据 TEC 和 REC 判断错误状态。错误较少时处于 Error Active；错误累计后进入 Error Passive；发送错误持续增加并达到阈值后进入 Bus Off，停止参与总线通信。

问题 2：CAN FD 相比 Classic CAN 有哪些变化？

回答：CAN FD 支持最大 64 字节数据，可通过 BRS 在数据段提高速率，并增加 ESI 和更强 CRC。仲裁段仍使用 Nominal Bit Rate。

问题 3：过滤器是否会减少总线上的报文？

回答：不会。过滤器只决定本节点控制器接收哪些报文，不能阻止其他节点发送，也不会降低物理总线负载。

问题 4：为什么 Rx FIFO 会溢出？

回答：CPU 或 ISR 读取速度低于报文到达速度，或者中断被长时间屏蔽。解决时需要缩短 ISR、使用软件队列、优化过滤器，并评估总线负载。

问题 5：发送成功中断是否代表业务对端已经处理？

回答：不代表。它通常只说明本帧已完成总线发送并获得 ACK。ACK 只表示至少一个节点正确接收了帧，不能证明目标业务已经解析或执行。

问题 6：Bus Off 后是否应该立即重新初始化？

回答：不应无条件立即恢复。需要遵循控制器和协议要求，增加等待与次数限制，并通知上层。持续快速恢复可能让故障节点反复干扰总线。

6. DMA

6.1 DMA 的使用场景

DMA 是独立于 CPU 的数据搬运单元，常用于外设与内存之间的大量或持续数据传输。

典型场景：

  1. UART 不定长或高速数据接收
  2. SPI 大块数据收发
  3. ADC 连续采样
  4. IIC 长数据块传输
  5. 音频、摄像头和显示数据搬运
  6. Memory-to-Memory 数据复制

DMA 的核心价值是降低 CPU 搬运数据的开销，而不是无条件提高外设本身的传输速率。

6.2 DMA 的核心机制

6.2.1 Request、Channel 与 DMAMUX

外设产生 DMA Request，DMAMUX 将请求路由到指定 DMA Channel，DMA Channel 根据配置执行搬运。

6.2.2 地址与计数

DMA 配置的核心参数包括：

  • Source Address
  • Destination Address
  • Transfer Width
  • Transfer Count
  • Source/Destination Increment
  • Burst Length

6.2.3 传输模式

  • Peripheral to Memory
  • Memory to Peripheral
  • Memory to Memory
  • Normal Mode
  • Circular Mode
  • Ping-Pong / Double Buffer
  • Scatter-Gather / Linked List

6.2.4 完成与错误通知

常见事件：

  • Half Complete
  • Transfer Complete
  • Transfer Error
  • Channel Abort

中断或回调只用于确认硬件状态和通知任务，不应该承载复杂业务处理。
